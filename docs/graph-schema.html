Graphiti graph schema

What Graphiti stores in its graph database: four node types, five edge types, how they connect, and what each is for. Source of truth: graphiti_core/nodes.py, graphiti_core/edges.py. The diagrams load Mermaid from a CDN, so open this page with network access.

1. Overview

Graphiti builds a temporal knowledge graph from a stream of episodes (messages, text, JSON). An LLM extracts entities and the facts relating them; the facts are stored as edges that carry validity times, so the graph records both what is true now and what used to be true. Every node and edge has a group_id, the tenant or partition the data belongs to.

2. Node types

Common to all nodes (Node)

PropertyTypeMeaning
uuidstringPrimary key; a random UUID4 unless supplied.
namestringDisplay name (entity name, episode name, community name, saga name).
group_idstringPartition of the graph. Search and bulk operations are scoped by it; some backends map it to a database or graph per group.
labelslist<string>Extra labels. Labels must be safe identifiers (letters, digits, underscore).
created_atdatetimeWhen the node was created (ingestion time, UTC).

Entity

Used for: the nouns of the knowledge graph. Entities are deduplicated across episodes (by name similarity, embedding and LLM resolution) so that "Alice", "Alice Smith" and "she" converge on one node. An entity always carries the label Entity; an optional user-defined type (for example Person, Company) is added as a second label and its custom fields land in attributes.

PropertyTypeMeaning
name_embeddinglist<float> | nullVector of the name; used for similarity search and for deduplication.
summarystringLLM-written summary of what the graph knows about the entity, refreshed as new episodes arrive.
attributesmapFree-form fields from custom entity types. Stored as flattened properties on most backends and as one JSON string on Kuzu and TigerGraph.

Episodic

Used for: provenance. Each call to add_episode stores the raw input as an episode, then links it to every entity extracted from it. Episodes give "where did this fact come from" and supply the context window (the last n episodes) for later extraction. They are also searchable by fulltext.

PropertyTypeMeaning
sourceenum message | json | textKind of input and how it is parsed. message content is "actor: text".
source_descriptionstringFree-text description of where the data came from.
contentstringThe raw episode body.
valid_atdatetimeWhen the described events happened (the episode's reference time), as opposed to created_at, when it was ingested.
entity_edgeslist<string>uuids of the RELATES_TO facts extracted from this episode.
episode_metadatamap | nullCustomer-defined key/values for filtering.

Community

Used for: a coarse, high-level view. A label-propagation pass over the entity graph groups densely connected entities; an LLM summarises each group. Communities answer broad questions ("what is going on around project X") and are searched by name and summary. They are built on demand (build_communities) and updated incrementally with update_communities.

PropertyTypeMeaning
name_embeddinglist<float> | nullVector of the community name.
summarystringLLM summary of the member entities; larger communities are summarised by merging child summaries pairwise.

Saga

Used for: grouping episodes that form one narrative, such as a chat thread or the chapters of a document, so that their story can be summarised incrementally. add_episode(..., saga='name') finds or creates the saga for the group_id, links the episode with HAS_EPISODE and chains it to the previous one with NEXT_EPISODE. summarize_saga then summarises only episodes added since the last summary.

PropertyTypeMeaning
summarystringRunning summary of the saga.
first_episode_uuid, last_episode_uuidstring | nullEnds of the episode chain.
last_summarized_atdatetime | nullIngestion-time watermark: the next summary takes episodes with created_at after this.
last_summarized_episode_valid_atdatetime | nullEvent-time watermark: the latest valid_at covered by the current summary.

Not persisted: four in-memory counters (_summary_episodes_*) describing the last summarise run.

3. Edge types

Common to all edges (Edge)

PropertyTypeMeaning
uuidstringEdge key. Several edges may join the same pair of nodes, so it is what tells them apart.
group_idstringPartition.
source_node_uuid, target_node_uuidstringEndpoints.
created_atdatetimeIngestion time.

RELATES_TO (EntityEdge): the fact

Used for: the knowledge itself. A fact such as "Alice works at Acme" is one edge from Alice to Acme. Contradicting facts are not overwritten; the older edge is invalidated and the newer one added, so history is preserved. Two entities can have many facts between them.

PropertyTypeMeaning
namestringThe relation type in SCREAMING_SNAKE_CASE (WORKS_AT). The special name IS_DUPLICATE_OF marks a detected duplicate entity pair.
factstringThe statement in natural language; fulltext-searched.
fact_embeddinglist<float> | nullVector of fact; similarity search, and finding facts that a new fact may contradict.
episodeslist<string>uuids of the episodes that support the fact.
valid_atdatetime | nullWhen the fact became true.
invalid_atdatetime | nullWhen it stopped being true in the world.
expired_atdatetime | nullWhen Graphiti learned it was superseded (system time).
reference_timedatetime | nullReference time of the episode that produced the edge.
attributesmapFree-form fields from custom edge types.

MENTIONS (EpisodicEdge)

Episodic → Entity. No properties beyond the common ones. Answers "which episodes talk about this entity", drives the episode-mentions reranker (entities mentioned in more episodes rank higher), and is followed by BFS search so a search can start from an episode.

HAS_MEMBER (CommunityEdge)

Community → Entity, or Community → Community when communities are nested. No extra properties. Used to find the community of an entity and to list a community's members.

HAS_EPISODE (HasEpisodeEdge)

Saga → Episodic. No extra properties. Lists a saga's episodes.

NEXT_EPISODE (NextEpisodeEdge)

Episodic → Episodic. No extra properties. Records the order of episodes within a saga (previous → next).

4. The bi-temporal model on facts

A fact has two timelines. Event time (valid_at, invalid_at) says when it was true in the world. System time (created_at, expired_at) says when Graphiti recorded it and when it learned it was no longer current. A fact is currently valid when expired_at and invalid_at are null.

timeline title "Alice works at Acme" then "Alice works at Beta" 2020-01 : fact 1 valid_at (Alice joins Acme) 2023-06 : fact 2 valid_at (Alice joins Beta) : fact 1 invalid_at 2023-07 : episode ingested, fact 2 created_at : fact 1 expired_at
Searches filter on these four fields (SearchFilters.valid_at / invalid_at / created_at / expired_at), so "what was true in March" and "what is true now" are the same query with different filters. Backends without a NULL (TigerGraph) store an absent time as an empty value, and the driver treats it as null.

The default hybrid search runs fulltext, vector and BFS legs, fuses them with reciprocal-rank fusion and optionally reranks. Similarity scores are scaled to (1 + cosine) / 2 on every backend, so the default minimum score 0.6 means the same thing everywhere.
